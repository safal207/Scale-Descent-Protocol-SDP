# Virality Strategy for SDP

This document defines a legitimate virality loop for Scale Descent Protocol (SDP).

The goal is not hype for its own sake. The goal is to make the core idea easy to repeat, criticize, test, and contribute to.

## Core Viral Hook

> Do not just ask whether an AI output is correct. Ask whether the action had a valid causal path.

## One-Sentence Positioning

SDP is a protocol for moving causal state to the scale where action becomes verifiable.

## Short Taglines

- Scale down to the cause.
- Do not execute from the cosmic view.
- Move state, not global context.
- No Execute before causal descent.
- From mobile qubits to mobile causal states.
- Causal subsidiarity for agentic AI.

## The Meme

Current agent systems mostly scale outward:

```text
more agents -> more tools -> more context -> more coupling -> more hidden failure
```

SDP scales inward:

```text
macro task -> micro transition -> pico evidence -> commit -> execute
```

## Viral Loop

1. Publish a simple claim.
2. Ask for failure examples.
3. Convert examples into trace fixtures.
4. Add fixtures to the repo.
5. Run SDP checks against them.
6. Publish what SDP catches and what it misses.
7. Invite criticism and new examples.

## Community Challenge

Ask the community:

> Show us an AI agent output that looked useful, but had an invalid causal path.

The best examples become:

- benchmark fixtures,
- documentation examples,
- issue discussions,
- paper case studies,
- demo traces.

## Launch Channels

### GitHub

- Pin the repo.
- Use clear README slogans.
- Keep Issues active.
- Turn community examples into fixtures.
- Add labels: research, benchmark, failure-example, good-first-issue.

### X / Twitter

Use short, sharp claims. Avoid long explanations in the first post. Put the deeper architecture in replies.

### Hacker News / Show HN

Launch only when the repo has:

- a working CLI demo,
- a clear README,
- examples,
- tests,
- a community question,
- a non-hype explanation.

Possible title:

```text
Show HN: SDP - a Rust protocol for checking causal paths before AI agents execute
```

### LinkedIn

Use the governance and engineering framing:

> Agent safety is not only about final-answer evaluation. It is also about whether the action had valid provenance, permission, and evidence before execution.

## First 7-Day Sprint

### Day 1

Publish the core thesis:

> Scalable agent safety requires moving causal state, not wiring every agent to every context.

### Day 2

Publish the family/governance analogy:

> Healthy systems do not centralize every decision. They move responsibility to the scale where cause is visible.

### Day 3

Publish a concrete failure scenario.

### Day 4

Invite community examples.

### Day 5

Add one community-inspired fixture.

### Day 6

Publish CLI output from the fixture.

### Day 7

Summarize the week:

- what SDP caught,
- what it missed,
- what needs reviewers.

## Anti-Hype Rules

- Do not claim SDP solves AI safety.
- Do not claim quantum inspiration as proof.
- Do not use fake stars, fake engagement, or paid manipulation.
- Do not overstate benchmark results before benchmarks exist.
- Do not call it a framework when it is a protocol layer.

## Desired Reaction

The ideal response is not only applause.

The ideal response is:

> I have an example where an agent executed too early. Can SDP represent it?

That is the viral loop.
